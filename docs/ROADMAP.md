# Remaining milestones

1. **Independent musical review:** obtain the user's chorale, compare extracted timing to notation, annotate findings with a named reviewer, and refine configurable conventions.
2. **Model teaching adapter:** choose an existing model, send only explicit user-authorized scores, consume structured candidate edits, validate the edits against IDs and constraints, and recheck before any validity claim. The existing teaching packet supplies the evidence contract; no provider is connected yet.
3. **Richer revision:** bounded multi-note search in both soprano-preserving and all-voice modes, followed by musician-reviewed melody/phrase comparisons. Do not equate few checker warnings with good composition.
4. **Interface:** MusicXML upload, structured assignment editor, rendered notation with linked findings, playback and interactive revision comparison. Annotated PDF export is implemented through MuseScore, with explanations beneath the score and a separate checked-correction page. Engraving remains separate from the musical model.
5. **Dataset:** maintain separate theory/explanation and musical-preference collections. Each record needs source, usage rights, composition-family ID (including transpositions), reviewer, review status, assignment, original score, verified findings and checked revisions. Keep unreviewed generation separate from trusted records.
6. **Evaluation:** split by composition family; measure missed findings, false alarms, exact locations, harmonic-label agreement, repair regressions and explanation evidence alignment. Compare a prompted baseline to checker-grounded outputs using the same model. Fine-tune only after identifying recurring weaknesses supported by reviewed data.

Complete diatonic seventh chords and basic seventh-resolution advice are now supported. Contextual/incomplete-chord interpretation, suspensions, modulation, chromatic harmony, audio transcription, score-image recognition and free composition remain outside the prototype.
